# 交互走查与反例

本记录验证 Demo 的产品路径和表述边界，不代表账号增长效果或平台实时数据效果。

| 编号 | 路径 / 反例 | 期望行为 |
| --- | --- | --- |
| RUN-01 | 用户不知道自己处于哪个阶段 | 页面收集内容状态、读者反馈与当前卡点，给出阶段建议和理由；用户可修改。 |
| RUN-02 | 内容起步、反馈不足 | 推荐找到方向，选题比较相邻读者问题，不提前要求做系列。 |
| RUN-03 | 内容分散但已有收藏 | 推荐确认有效内容，三个选题围绕同一问题比较表达方式。 |
| RUN-04 | 同类内容持续有反馈 | 推荐做成内容系列，选题按读者理解路径连续组织。 |
| RUN-05 | 问题集中在标题、开头或结构 | 推荐针对性调整，每次只改变一个变量。 |
| RUN-06 | 连续保存两条内容计划 | 两条行动同时存在于队列，后一条不能覆盖前一条。 |
| RUN-07 | 一条行动待撰写，一条已发布 | 队列准确分别显示待撰写与等待观察状态。 |
| RUN-08 | 进入复盘 | 用户必须选择一条已发布行动；复盘页面显示该行动的原始观察目标。 |
| RUN-09 | 复盘结果为“信号还不稳定” | 推荐继续探索或验证，不强制升级为系列。 |
| RUN-10 | 复盘结果为“问题集中在一个环节” | 推荐针对性调整，并明确只改一个变量。 |
| RUN-11 | 保存本轮判断 | 记录必须包含信号、理解、保留或调整、下一轮验证，并绑定到具体行动。 |
| RUN-12 | 开始下一轮 | 使用最近判断记录的推荐阶段；用户仍可以返回阶段判断修改。 |
| RUN-13 | 活动或链接素材 | 显示来源、可借用角度、对本轮的帮助和暂不采用的情况；不因“热门”自动进入计划。 |
| RUN-14 | 用户输入非链接文本 | 拒绝保存并提示输入有效的 http/https 链接。 |
| RUN-15 | 连续保存两条不同内容行动 | 每条均保留自己的“写给谁、核心主张、开头场景、素材”简报，编辑其中一条不会覆盖另一条。 |
| RUN-16 | 复盘一条以收藏为目标的内容 | 同时显示本条信号、近期同类内容基准与本轮观察目标，再提示可能说明什么。 |
| RUN-17 | 复盘一条以“看懂场景”为目标的内容 | 明确数据只能作为辅助线索，是否看懂仍需结合评论判断，不能把互动直接包装成理解证明。 |

## 关键边界

1. 用户选择或补充的信息只是判断依据，不代表系统已经读取完整账号。
2. 单条内容的数据不能证明固定公式有效。
3. 内容计划保存不等于内容已发布；只有用户标记发布后才进入复盘。
4. 复盘结论必须绑定到一条行动，不能成为脱离内容的泛化建议。
5. 阶段推荐不是固定升级路径，也不替用户做最终决定。
6. 链接只能证明用户添加了一项外部素材，不能证明平台已读取、认证或认可其内容。
7. 对比基准属于体验账号的近 7 日数据；未接入用户真实账号时，不能把它表述为平台平均值或用户真实成绩。
