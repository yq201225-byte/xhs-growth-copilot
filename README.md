# 小红书运营 Copilot

帮助创作者判断：账号现在更适合做什么、这条内容为什么值得做，以及发布后下一步如何调整。

# 它解决什么问题

很多人不是不会发内容，而是不知道：

- 自己现在处于探索、验证、系列化还是优化阶段；
- 此刻该围绕什么问题做内容；
- 一条内容发布后，该从哪些信号判断是否继续；
- 下一轮应该保持方向、验证表达，还是只调整一个环节。

产品将一次运营过程组织为持续循环：

`阶段判断 → 内容策略 → 内容行动 → 复盘回流`

# 核心体验

 1. 阶段判断

用户补充已有内容、近期反馈和当前卡点后，系统给出更适合优先进行的阶段建议，并说明判断依据。用户可以修改判断，不会被固定在某个阶段。

# 2. 内容策略与选题规划

围绕当前阶段和本轮要验证的问题，提供可继续展开的内容方向与候选选题。每个方向对应不同的行动重点，而不是生成一组无关的热点标题。

# 3. 内容行动

每一条计划都保留一个轻量内容简报：

- 写给谁；
- 核心主张；
- 开头场景；
- 需要准备的素材；
- 发布后重点观察的一个信号。

行动会进入队列，按“待撰写 → 已发布 → 已复盘”持续推进。

# 4. 账号复盘

复盘绑定到具体已发布内容，而不是只展示一张数据看板。用户先看这条内容原本想观察什么，再结合本次信号、近期同类内容表现与本轮目标，记录：

- 看到了什么信号；
- 这说明什么；
- 下次保留或调整什么；
- 下一轮还要验证什么。

系统会推荐下一阶段，但不强制线性升级：信号不足可以继续探索，问题集中可以局部优化，重复信号出现后才建议系列化。

# 页面入口

- `工作台`：查看当前阶段、本轮策略、行动队列和待复盘内容。
- `内容方向`：完成阶段判断，获得可调整的策略建议。
- `选题规划`：选择与当前策略关联的内容行动。
- `内容计划`：编辑并保存内容简报，管理行动状态。
- `复盘`：选择具体行动，记录判断并获得下一轮建议。
- `热点研究`：收集活动、公开讨论或外部链接，判断是否值得进入当前内容计划。

# 本地打开

直接打开 `index.html`，或在项目目录启动一个静态网页服务后访问。

# 仓库结构

- `index.html`：页面入口。
- `app.css`：视觉与响应式样式。
- `app.js`：页面状态、阶段判断、行动队列和复盘交互。
- `docs/product-brief.md`：产品简报。
- `docs/workflow.md`：核心流程说明。
- `docs/eval-and-badcase.md`：关键路径与反例检查记录。

# 项目边界

产品帮助用户整理判断和行动，不自动发布内容，也不把单次内容数据包装成增长结果。页面中的数据用于呈现创作者如何结合信号做下一轮决策。
